# Build And Deploy

## Vivado 2025.2

Run from the repository root in PowerShell. This writes generated files under the ignored `build/vivado/zynq7020_bringup/` directory.

```powershell
& 'C:\AMDDesignTools\2025.2\Vivado\bin\vivado.bat' `
  -mode batch `
  -source .\hardware\vivado\create_zynq7020_bringup.tcl
```

Expected outputs:

```text
build/vivado/zynq7020_bringup/zynq7020_bringup.xsa
build/vivado/zynq7020_bringup/zynq7020_bringup.runs/impl_1/system_wrapper.bit
```

## Buildroot In WSL2

Keep the build tree on WSL's Linux filesystem. From Windows PowerShell, sync this checkout to a separate staging directory so an existing WSL project is not overwritten:

```powershell
$wslSource = (& wsl.exe -d Ubuntu-22.04-Buildroot --exec wslpath -u (Get-Location).Path).Trim()
wsl.exe -d Ubuntu-22.04-Buildroot --exec mkdir -p /home/builder/work/zynq7020-bringup-jtag
wsl.exe -d Ubuntu-22.04-Buildroot --exec rsync -a --exclude .git --exclude build --exclude .buildroot `
  "$wslSource/" /home/builder/work/zynq7020-bringup-jtag/
```

In WSL Ubuntu:

```bash
cd ~/work/zynq7020-bringup-jtag
./buildroot-external/scripts/setup_ubuntu.sh
./buildroot-external/scripts/bootstrap_buildroot.sh
./buildroot-external/scripts/make_jtag_assets.sh build/buildroot-zynq7020/images
```

The first Buildroot run downloads Buildroot, the external ARM toolchain, and the Xilinx Linux source. The output is `build/buildroot-zynq7020/images/`. The JTAG defconfig does not require an SD card or `rootfs.ext4`.

The kernel includes the patch in `buildroot-external/patches/linux/`. When reusing a kernel tree created before this patch, run `make -C build/buildroot-zynq7020 linux-dirclean`, then rerun the bootstrap script. That target removes only generated Linux build files in the WSL output tree. Bash requires both `BR2_PACKAGE_BASH` and `BR2_PACKAGE_BUSYBOX_SHOW_OTHERS`; the script checks that Kconfig actually selected it.

Copy the assets to the Windows checkout:

```powershell
.\scripts\copy_jtag_assets_from_wsl.ps1 `
  -Distro Ubuntu-22.04-Buildroot `
  -WslRepo /home/builder/work/zynq7020-bringup-jtag
```

The script copies `zImage`, `rootfs.cpio.gz`, `zynq7020-bringup.dtb`, matching `System.map`, and `sdcard.img` into `build/linux_images/`.

The initramfs network script tries DHCP, then falls back to `192.168.7.2/24`, gateway `192.168.7.1`, and DNS `1.1.1.1`. Local ping requires the PC's USB Ethernet adapter to use `192.168.7.1/24`; Internet access additionally requires host NAT for `192.168.7.0/24` with the PC's Wi-Fi/default route as the upstream. Host NAT is outside Buildroot and is not configured by the JTAG scripts.

## PS Initialization File

`build/jtag_hw/ps7_init.tcl` is generated by Vivado and is not a hand-written substitute. The XSA contains the generated file. After each Vivado build, extract it with:

```powershell
.\scripts\extract_ps7_init.ps1
```

The script reads `ps7_init.tcl` from `build/vivado/zynq7020_bringup/zynq7020_bringup.xsa` and writes it to `build/jtag_hw/ps7_init.tcl`. If the XSA does not contain that generated entry, it fails instead of creating a placeholder. Vitis is still used for XSCT/JTAG; an FSBL is not run by this JTAG flow.

## JTAG Commands

First run the non-persistent preflight test, then boot the Linux image:

```powershell
.\scripts\extract_ps7_init.ps1
& 'C:\AMDDesignTools\2025.2\Vitis\bin\xsct.bat' .\hardware\vivado\jtag_preflight.tcl
& 'C:\AMDDesignTools\2025.2\Vitis\bin\xsct.bat' .\hardware\vivado\jtag_boot_bringup.tcl
```

The preflight resets the Zynq, initializes PS DDR, writes two test words near the top of DDR, reads them back, restores the original words, and checks that the Cortex-A9 can be resumed and halted. The boot script programs only volatile PL configuration and DDR; it does not issue QSPI or SD writes.

## JTAG DDR Map

| Payload | Address | Limit / purpose |
| --- | ---: | --- |
| `zImage` | `0x02000000` | Raw compressed kernel image; region ends before initramfs |
| `rootfs.cpio.gz` | `0x06000000` | Initramfs; its exclusive end is recorded in `/chosen` |
| `zynq7020-bringup.dtb` | `0x07000000` | Device Tree passed in `r2` |
| DDR end | `0x20000000` | 512 MiB configured range |

The helper checks file sizes and overlap before modifying the DTB. The Linux ARM boot protocol registers are `r0=0`, `r1=0xffffffff` (DT-only machine ID), and `r2=DTB address`.

## Flash And SD

The Buildroot post-image hook creates `sdcard.img` with kernel, DTB, initramfs and `boot.scr`, generated from `boot.cmd` by host mkimage. It does not include a bitstream or BOOT.BIN, and it does not use rootfs.ext4. `create_zynq_fsbl.tcl` and `package_qspi_boot.tcl` package the current bitstream and preserved original U-Boot for QSPI. The tracked FSBL handoff hook clears stale UART RX before entering U-Boot. Explicit write/verify steps, safeguards, backup details and actual results are in [Boot Media](BOOT_MEDIA.md). Neither build nor direct JTAG loading automatically writes persistent media.
