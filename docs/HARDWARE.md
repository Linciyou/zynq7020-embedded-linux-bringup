# Hardware Design

The Vivado design is generated by `hardware/vivado/create_zynq7020_bringup.tcl` for `xc7z020clg484-2`.

## Processing System

- PS7 DDR, fixed I/O, FCLK0 at 100 MHz, FCLK1 at 200 MHz, and reset configuration remain enabled.
- QSPI holds the boot image; SD0 provides the software-only Linux images for standalone boot.
- UART1 uses EMIO and the board CH340E pins for the Linux console. It is not required by the JTAG loader.
- GEM0 is enabled on EMIO for GMII and MDIO.

## Programmable Logic

The PL contains only the support logic still required by the board connections:

- `gmii_to_rgmii_0`: GEM0 GMII to external RTL8211E RGMII.
- `mdio_iobuf_0`: bidirectional MDIO electrical interface.
- 200 MHz `proc_sys_reset` block for the Ethernet bridge.
- 100 MHz AXI GP0 interconnect and `axi_gpio_phy_reset` at `0x41210000`, driving the PHY reset output on H17.

The Device Tree configures an active-low PHY reset GPIO, 10 ms assertion, and 50 ms post-release delay. The RTL8211E datasheet calls for at least 10 ms reset-low and 30 ms before MDIO access. No oscilloscope capture was made, so timing at the physical PHY pin is not verified.

## Schematic Cross-Check

The source is the repository's Zynq-7000 schematic PDF; Ethernet is on PDF page 5 and the FPGA Bank 35 pin map is on page 7.

| Schematic signal | Strap / FPGA pin | Design setting |
| --- | --- | --- |
| RTL8211E LED0 / PHYAD[0] | R33, 5.1 kOhm pull-up | PHYAD[0] = 1 |
| RTL8211E LED1 / PHYAD[1] | R34, 5.1 kOhm pull-up | PHYAD[1] = 1 |
| RTL8211E RXCTL / PHYAD[2] | R41, 5.1 kOhm pull-down | PHYAD[2] = 0 |
| PHY MDIO / MDC | FPGA H22 / G21 | `eth_mdio` / `eth_mdc` in XDC |
| PHY reset (`PHYRSTB`) | R45 5.1 kOhm pull-up and C50 1 uF to ground; R46 is marked NC | H17 AXI GPIO is toggled by Linux; continuity to `PHYRSTB` is not confirmed |

The three address straps imply `PHYAD[2:0] = 3'b011` (address 3), but the tested Linux image bound the RTL8211E at address 1. The current DTS uses address 1 because that is the observed working address. The GMII-to-RGMII bridge remains at address 8. RGMII data/control/clock and MDC/MDIO pin assignments in `zynq7020_rgmii.xdc` were cross-checked against the Bank 35 pin map on page 7. The PHY linked at 1 Gbps/full duplex; the schematic/assembly discrepancy still needs board-level inspection.

The board did not provide a valid factory GEM MAC address, so this single-board lab configuration sets `local-mac-address = 02:00:00:70:20:01`. This locally administered address makes packet tests repeatable; replace it with a unique board address before deploying or testing multiple boards.

The same JTAG Linux run configured `eth0` as `192.168.7.2/24`, with default gateway `192.168.7.1`. The host's existing active Windows NAT for `192.168.7.0/24` carried a Linux ping to `1.1.1.1` and a DNS lookup for `example.com`. DHCP returned no lease and the initramfs deliberately fell back to the static direct-link configuration.

An earlier image logged `unable to generate target frequency: 125000000 Hz`. The final MACB patch preserves the GEM clock gate but skips rate programming for the externally clocked Zynq GMII path. The final image has no such warning and passed binary transfer tests. This is not a sustained peak-throughput measurement; see [UART and Ethernet Debugging](UART_ETHERNET_DEBUG_STORY.md).

The reset timing requirement is from the [RTL8211E/RTL8211EG datasheet](https://www.t-firefly.com/download/fireprime/hardware/RTL8211E%28G%29-xx-CG_DataSheet_1.3.pdf), section 7.16.

MACB/GEM owns the MAC registers and clock gate; PHYLIB/Realtek owns PHY negotiation; the Xilinx bridge driver sets converter speed over MDIO. The board DTS connects GEM0 to PHY address 1, bridge address 8, and the reset GPIO. There is no custom network driver.

## Design Checks

The Tcl runs `validate_bd_design`, implementation, bitstream generation, and XSA export. The DDR part/width/frequency and MIO mapping must still be checked against the actual board schematic and Vivado reports before treating the exported platform as electrically validated.
The ZC702 base tree aliases PS UART1 as `serial0`; Linux therefore exposes that port as `ttyPS0`. The JTAG bootargs and Buildroot getty use this name.
